# Serena Memories Index

## Purpose
Implementation knowledge base: "How it's done" + "Why it's done"

## Files

| File | When to Read | Content |
|------|-------------|---------|
| **decisions.md** | Architecture design, tech selection | Core technical decisions |
| **known_issues.md** | Debugging, errors | Known bugs and workarounds |
| **current_tasks.md** | Session start | Ongoing cross-session tasks |
| **quick_ref.md** | Executing commands | Docker/DB/API info |

## Usage Rules

**Session Start**: Always read `current_tasks.md`
**During Work**: Read relevant memory when needed
**Session End**: Update `current_tasks.md` if task incomplete

## What to Write
- 3rd-party library bugs/workarounds
- Docker/DB practical experiences
- Architecture decision context
- Environment-specific configs

## What NOT to Write
- Code style rules → AGENTS.md
- API/DB schemas → docs/
- General principles (SOLID, KISS)
