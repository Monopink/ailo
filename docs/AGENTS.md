# 文档编写原则

## 方案文档原则

- plans 目录下的文档为方案文档
- 非持久性文档，只作为本次任务指导
- 描述无歧义，不应该包含任何建议语气

## 项目文档原则

- 非 task、references 目录下文档为项目文档
- 以对未来提供指导和规范为原则，记录系统设计和规范，不应该包含过多实施描述、AI知晓的原则、标准等
- 必须始终对齐当前实现或即将实现内容，禁止保留变化历史
- 禁止包含建议、技术优势、设计理念、实施方案、问题描述、未来规划等
- 只说“是什么”，不说“不是什么”
- 找到正确位置插入，不要简单追加
- 修复问题的场景，如果文档没有错误，不需要额外增量修改
- 增加新功能的场景，增量修改同时，合理精简已经没有参考价值的内容
- 如果要写入的内容没有对应的文件，需要创建新的文档，需要经过用户的同意
