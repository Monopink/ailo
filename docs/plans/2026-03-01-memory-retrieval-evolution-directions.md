# 记忆检索演进方向（QMD 思路参考）

本文档记录未来可选的记忆检索演进方向，用于架构评估与后续立项参考，不定义具体实施任务。

## 目标边界

- 记忆写入事实源保持不变：`ai_instance_memories`。
- 记忆操作协议保持不变：`remove -> update -> refresh -> add`。
- 消息处理保持“发送优先”：消息可发送时优先发送；会话副作用失败不回滚已发送消息。
- 安全副作用保持强约束：`attack_detected`、`should_block` 失败时终止发送路径。

## 当前系统基线

- 记忆结构：`core/recent` 两类，`importance` 决定 recent 寿命。
- 检索方式：按 `importance desc, created_at desc` 裁剪，替换 `{{memory}}`。
- 配置层次：`instance.request_params -> llm_config.extra_params -> DEFAULT_MEMORY_LIMITS`。
- 特征：一致性强、实现简单、运行成本低、可解释性强。

## QMD 可借鉴能力映射

- 词法检索（BM25）能力：用于关键词精确匹配与排除。
- 语义检索（向量）能力：用于表达不一致但语义相近的召回。
- 混合融合能力：词法与语义结果融合后再重排。
- 上下文描述能力：通过路径/分层描述提升召回结果可解释性。

## 不直接照搬的部分

- QMD 的 Node.js + 本地 GGUF + `node-llama-cpp` 运行时不进入主服务链路。
- QMD 的 Markdown 文档集合模型不替代实例化结构化记忆表模型。
- QMD 的独立 MCP 服务形态不直接作为在线业务依赖。

## 演进方向分层（由轻到重）

| 方向 | 核心能力 | 架构改动面 | 实施复杂度 | 延迟影响 | 资源成本 |
|---|---|---|---|---|---|
| A 词法增强 | 在实例记忆上增加词法检索与权重排序 | 低（检索层） | 低 | 低 | 低 |
| B 语义召回 | 记忆向量化与语义检索 | 中（数据层+检索层+离线任务） | 中高 | 中 | 中高 |
| C 混合召回+重排 | 词法+语义融合，重排输出 prompt 记忆片段 | 高（检索层+模型依赖+观测体系） | 高 | 中高 | 高 |

### 方向 A：词法增强（结构化记忆内）

- 在 `ai_instance_memories` 内增加词法可检索能力（关键词命中、短语命中、排除词）。
- 保持现有寿命、归档、状态逻辑不变。
- 适配场景：记忆条目增长到中等规模后，纯 `importance/time` 排序不再稳定。

### 方向 B：语义召回（结构化记忆向量化）

- 为记忆内容建立向量索引，查询时基于当前轮用户输入做语义召回。
- 维持“结构化记忆事实写入 + 检索可变”的分层：写入协议不改，检索策略可插拔。
- 适配场景：用户表达和记忆文本经常不一致，词法命中率持续偏低。

### 方向 C：混合召回 + 重排

- 组合词法结果与语义结果，融合后再重排，最后生成 `{{memory}}` 片段。
- 需要完整观测体系支撑：召回命中、重排收益、延迟与成本曲线。
- 适配场景：高记忆密度、高对话轮次、对“记得准”要求显著上升。

## 性能与成本画像

- 当前基线（结构化裁剪检索）在实例记忆规模较小时成本最优。
- 词法增强主要增加索引与查询复杂度，在线延迟增幅可控。
- 语义召回引入离线向量生成与在线 ANN 检索，CPU/内存/存储成本显著上升。
- 混合召回与重排进一步引入模型推理成本，需做限流、缓存和降载策略。

## 立项触发信号

- 用户侧出现稳定“记不住/记错”反馈并可复现。
- 单实例活跃记忆规模增长到现有裁剪策略无法稳定命中。
- 线上观测显示：记忆命中率与回复质量相关指标持续下降。
- 现有检索策略导致 prompt token 利用率下降且不可通过参数调优修复。

## 架构不变项

- 记忆写入协议、事务语义、审计链路保持现有约束。
- 消息发送链路不依赖语义检索结果的“必达”成功。
- 检索层异常不扩散到消息发送事实层。
- 安全副作用与会话副作用的优先级关系保持当前规范。
