# 生产环境技术方案（腾讯云）

## 已确认决策

- 生产地域基线为腾讯云上海：`ap-shanghai`。
- 计算资源采用腾讯云 `CVM`，不使用轻量应用服务器。
- 首发实例规格采用 `蜂驰型 BF1`，规格为 `2C4G`。
- 业务增长后按需从 `BF1` 升级为标准型实例，使用腾讯云实例调整能力完成跨实例族变配。
- 数据库采用 `CVM` 自建 PostgreSQL，达到数据库瓶颈前不切换云数据库。
- PostgreSQL 主版本固定为 `18`，先在开发环境执行升级测试并验证兼容性与迁移流程。
- 对象存储采用腾讯云 `COS`，业务媒资与数据库备份分桶管理。
- 后端生产进程数固定为 `uvicorn workers=1`，避免当前 WebSocket 进程内状态导致的跨进程扇出问题。
- 管理后台 `qiao-dash` 与管理接口 `admin-api` 保持公网可访问并统一启用 `Basic Auth`。
- 数据库不开放公网端口，数据库图形化工具统一通过 `SSH Tunnel` 访问。
- 生产环境中 `CVM`、PostgreSQL、COS 保持同地域部署。

## 架构基线

- 单台 `CVM` 承载：`Nginx + Backend + PostgreSQL`。
- 数据库与应用通过内网通信。
- 外部流量入口为 `Nginx`，后端服务仅对内暴露应用端口。
- COS 作为业务文件存储与数据库备份存储。

## 资源配置

### 1. CVM

- 实例族：`BF1`
- 规格：`2C4G`
- 系统盘：`>= 50GB`
- 数据盘：独立云硬盘，专用于 PostgreSQL 数据目录
- 操作系统：`TencentOS Server` 或稳定版 `Ubuntu LTS`

### 2. PostgreSQL

- 版本：`18.x`
- 部署方式：容器化部署（沿用现有部署结构）
- 数据目录：挂载到独立数据盘

### 3. COS

- `media` 桶：业务图片/文件
- `db-backup` 桶：数据库备份专用
- 备份桶开启：版本控制、生命周期、服务端加密

## 网络与安全

- 生产资源部署在同一地域同一 `VPC`。
- PostgreSQL 不开放公网访问，仅允许内网访问。
- 腾讯云安全组公网入站仅开放 `SSH`、`80`、`443`。
- 数据库远程管理统一通过 `SSH Tunnel`，不新增数据库公网入站规则。
- 生产密钥不写入仓库，统一使用环境变量或密钥管理服务注入。

## 应用部署策略

- 保持单实例部署。
- 后端进程参数固定 `--workers 1`。
- 生产启动参数位置：`backend/Dockerfile`（target: `prod`）。
- `qiao-dash` 与 `admin-api` 在 Nginx 层统一启用 `Basic Auth`。
- 后续扩容前置条件：完成 Redis Pub/Sub 方案并实现 WebSocket 跨进程广播。

## 数据库备份与恢复策略

### 1. 备份策略

- 每日执行两次逻辑备份（`pg_dump`），时间为 `03:30`、`12:30`（CST），压缩后上传 `db-backup` 桶。
- 每日执行云硬盘快照策略。
- 备份保留周期分层：
  - 近 7 天：标准存储
  - 8-30 天：低频
  - 31-90 天：删除

### 2. 恢复策略

- 每月执行一次恢复演练。
- 恢复演练必须验证：
  - 备份文件可下载
  - 数据可导入
  - 应用可正常连接并完成核心业务链路

## 成本控制策略

- 首发采用 `BF1 2C4G + 自建 PostgreSQL` 降低固定成本。
- 先按量计费验证实际负载，再切包年包月。
- 达到升级触发条件后再进行实例升级或数据库托管迁移。

## 升级触发条件

- 近 7 天内 CPU 持续高于 70% 且有明显请求积压。
- 数据库出现持续慢查询、锁等待或连接资源不足。
- 月度恢复演练无法稳定通过。
- 单机故障恢复时间无法满足业务目标。

满足任一条件时执行升级动作：

- `BF1 -> 标准型`。
- 评估 `自建 PostgreSQL -> 腾讯云托管 PostgreSQL` 迁移。

## 实施顺序

1. 确认生产地域与可用区。
2. 创建 `CVM`、`VPC`、安全组与云硬盘。
3. 在开发环境完成 PostgreSQL 主版本升级测试并定版生产版本。
4. 部署现有生产编排并固定 `workers=1`。
5. 初始化定版 PostgreSQL 与业务库。
6. 配置 `qiao-dash` 与 `admin-api` 的 `Basic Auth`。
7. 配置 COS 业务桶与备份桶。
8. 配置自动备份任务与快照策略。
9. 执行上线前验证与一次恢复演练。

## 验收清单

- 服务健康检查稳定通过。
- WebSocket 消息收发链路稳定，无跨进程漏发。
- 数据库仅内网可达，公网不可达。
- Navicat 通过 `SSH Tunnel` 可连接数据库并执行查询。
- 未通过 `Basic Auth` 无法访问 `qiao-dash` 与 `admin-api`。
- 每日备份任务成功并可在 COS 查询到当日备份产物。
- 恢复演练通过并形成演练记录。
- 关键配置与密钥未出现在仓库明文文件中。
