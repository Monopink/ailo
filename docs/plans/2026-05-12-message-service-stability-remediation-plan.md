# 2026-05-12 消息服务稳定性整改计划

## 文档状态

- 状态：已实施（待线上观察）
- 创建日期：`2026-05-12`
- 最后更新：`2026-05-12`
- 适用范围：后端 WebSocket 消息接入与分发链路、小程序消息连接与发送链路、客户端运行态故障上报链路

## 目标

1. 消息服务在运行中出现连接异常后可自动恢复，避免“持续发送失败直到重启小程序”的状态。
2. 启动流程保持非阻塞；消息发送入口承担连接等待与恢复责任。
3. 消息故障具备可检索、可关联的结构化上报能力，支持线上排查。
4. 仅实施与根因直接相关的改动，不引入与根因弱相关的参数调整与链路改造。

## 已确认决策

1. 启动流程保持非阻塞；不以消息服务初始化结果阻塞页面启动。
2. 消息发送入口执行连接等待；连接等待在有限时长内完成，超限快速失败。
3. 客户端健康定义保持“后端可用”，本轮不收紧健康口径。
4. 会话票据采用复用优先策略：未临近过期优先复用，临近过期或鉴权失败时刷新。
5. 故障上报复用 `client_runtime_observations`，不新增独立错误表。
6. 发送失败反馈时长上限保持在 5 秒内；本轮不实施延长发送超时的调整。

## 问题点（现态）

1. 连接状态机存在“连接状态与真实 socket 状态偏离”的风险，异常后可能停留在不可用状态。
2. 发送失败重试路径在部分异常类型下缺少“强制摘除坏连接并重建连接”的动作。
3. 初始化阶段允许连接失败继续完成初始化，易形成“页面可用、消息不可用”的长期状态。
4. 会话票据在连接路径上刷新频率偏高，增加连接抖动与重建频率。
5. 运行态上报白名单未覆盖消息服务故障事件，且去重策略会削弱高频故障可见性。

## 实施范围

### 小程序

1. 调整消息连接状态机：
   - 发送相关 ACK 超时、ping ACK 超时、socket error 命中后，统一执行坏连接摘除。
   - 坏连接摘除后触发连接状态迁移与重连调度。
2. 保持启动非阻塞；发送入口执行连接等待与有限时长重试。
3. 初始化语义收敛：初始化失败不得写入“初始化成功”状态。
4. 会话票据复用策略落地：
   - 连接前先校验本地票据有效窗口。
   - 鉴权失败或票据临近过期时刷新票据。
5. 新增消息故障运行态上报事件，覆盖连接失败、鉴权失败、ACK 超时、连接恢复。

### 后端

1. 扩展 `runtime-observations` 事件白名单，纳入消息服务故障事件名。
2. 为消息服务故障事件配置独立去重口径，保证短时间连续故障可观测。
3. 在 WebSocket 接入层补充结构化故障日志，覆盖鉴权失败、帧处理异常、连接关闭前关键上下文。

### 文档

1. 更新 `docs/api/client-review-runtime.md`：新增消息服务运行态事件契约与字段约束。
2. 更新消息链路相关 spec/api 文档，保证状态机与故障语义一致。

## 实施任务

### 1. 连接自愈与状态机收敛

1. 明确“可判定坏连接”的异常集合与统一处理函数。
2. 在发送 ACK 超时、ping ACK 超时、socket error 三类路径接入坏连接摘除。
3. 摘除后统一触发连接状态迁移与重连调度。

### 2. 初始化与发送门禁语义收敛

1. 启动路径保留非阻塞行为。
2. 发送路径执行连接等待与快速失败。
3. 初始化失败不得写入 initialized 成功态。

### 3. 会话票据复用策略

1. 在连接前判断票据有效窗口。
2. 票据刷新触发条件限定为“临近过期”或“鉴权失败”。
3. 保留现有会话票据接口契约。

### 4. 运行态故障上报扩展

1. 扩展后端白名单事件：
   - `message_connect_failed`
   - `message_connect_recovered`
   - `message_send_failed`
   - `ws_auth_failed`
   - `ws_ack_timeout`
2. 设计上述事件在 `event_payload` 的统一字段：错误码、错误消息、连接状态、页面路径、request_id、occurred_at_ms。
3. 调整消息故障事件去重策略，保留同一会话内连续故障样本。

## 验收标准

1. 复现场景中出现一次发送失败后，消息服务可在小程序进程内自动恢复，无需重启小程序。
2. 连接不可用场景下，发送入口在 5 秒内完成失败反馈。
3. 启动流程保持非阻塞，首页与聊天页加载不依赖消息服务初始化完成。
4. 会话票据请求频率下降，连接阶段不会因频繁刷新触发高频重建。
5. 后台可查询到消息服务故障事件，并可按 `device_id + session_id + event_name` 追踪连续样本。
6. 实施范围内 API/spec/plan 文档与代码行为一致。

## 实施结果

- 实施完成日期：`2026-05-12`。
- 已落地改动：
  - 小程序连接适配层新增坏连接强制摘除路径：`socket error`、发送 `ACK` 超时、发送失败统一触发连接重置与重连调度。
  - 小程序消息服务补充连接失败/恢复与发送失败运行态上报，并在初始化与连接载荷加载失败时执行显式断开态与重连调度。
  - 会话票据连接前改为复用优先，仅在临近过期或不可用时刷新，降低连接抖动。
  - 后端 `runtime-observations` 白名单已扩展消息服务事件，并对消息服务事件关闭“同日首条”去重。
  - 后端 WebSocket 鉴权拒绝与主循环异常补充结构化日志，支持失败链路定位。
- 本地验证结果：
  - 后端：`ruff format --check`、`ruff check`、`mypy`、`lint-imports` 全部通过。
  - 小程序：`npm run check` 通过（`type-check`、`eslint`、`stylelint`、`ui:audit`、`check:fallbacks`）。
- 待线上观察项：
  - 首次进入场景是否仍出现“info-bar 长时间连接中 + 消息持续失败直到重启”。
  - 故障事件上报量是否满足排查需要且无异常洪泛。
