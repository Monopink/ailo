# 备份通知系统缺口基线计划

## 背景状态

- 生产数据库备份能力按既定计划建设。
- 备份通知能力本期不开发。
- 通知能力作为后续独立任务推进。

## 当前缺口定义

- 缺少统一通知通道抽象层。
- 缺少多渠道通知适配能力。
- 缺少通知重试、降级与失败补偿机制。
- 缺少告警级别与路由策略管理。

## 后续任务目标

- 建设统一通知服务，承接备份成功/失败、恢复演练结果等运维事件。
- 支持多通知渠道统一接入与统一事件模型。
- 形成可审计、可重试、可扩展的通知能力。

## 范围边界

后续纳入范围：

- 统一事件模型
- 通知模板管理
- 多渠道适配（企业微信、邮件等）
- 发送结果审计与重试

后续不纳入范围：

- 业务主流程改造
- 数据库备份执行链路重构

## 对当前备份实施的约束

- 当前备份脚本必须输出标准化执行结果（成功/失败、开始时间、结束时间、耗时、对象键、校验值、错误信息）。
- 当前后台展示结构必须保留通知事件扩展字段占位。
- 当前任务不接入外部通知渠道。

## 预留数据结构要求

- 事件标识：`event_id`
- 事件类型：`event_type`
- 事件时间：`occurred_at`
- 事件级别：`severity`
- 执行状态：`status`
- 执行摘要：`summary`
- 结构化详情：`details`

## 后续实施入口

- 以本计划作为通知系统任务拆分输入基线。
- 与“生产数据库备份实施计划”对齐事件字段与状态口径。
- 通知系统上线后回填备份事件通知链路。
