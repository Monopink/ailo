# 2026-03-26 最小契约重试：纠错提示设计（暂不启用）

## 决策

- 不启用“重试纠错提示（correction prompt）”。
- 本文档仅记录设计与参数接线预留，避免后续实现时引入不可追溯的临时逻辑。

## 背景

- 最小契约重试用于处理 LLM 输出不满足最小可用字段（L0）时的重试。
- 纠错提示用于在第 2/3 次 attempt 强化输出约束，提高 L0 通过率。

## 纠错提示（未启用时的要求）

- 重试 attempt 不追加任何额外纠错提示。
- attempt 之间仅允许使用统一的重试控制参数（attempt 上限、backoff、启用开关），不允许隐式改变 prompt 或采样参数。

## 预留设计（未来启用时的行为定义）

### 触发条件

- 仅在 L0 最小契约校验失败时触发（包括 JSON 解析失败、字段缺失、类型错误、数组元素为空字符串/非字符串等）。
- 不因 L1 可选字段失败触发。

### 生效范围

- 仅影响后续 attempt 的系统指令拼接，不影响首个 attempt。
- 仅用于修复结构化输出，不用于改变业务语义。

### 纠错提示内容约束

- 仅包含：
  - 必须字段清单与类型（L0）。
  - 数组元素规则（必须为非空字符串）。
  - `should_reply=false` 时的消息字段处理模式说明（由常量开关决定）。
- 不包含：
  - 业务策略建议（例如“更友好/更强硬”等）。
  - 对用户可见的解释。

### 抢占与终止

- 任意时刻检测到 turn 抢占后，立即停止当前 attempt 与后续重试。
- 抢占后不得再追加纠错提示，不得再发起新 attempt。

## 参数接线预留

> 本节为预留定义，当前不启用。

- `ai_llm_min_contract_retry_use_correction_prompt`（bool）
  - `true`：启用纠错提示。
  - `false`：禁用纠错提示。
- `ai_llm_min_contract_retry_correction_prompt_mode`（string）
  - 取值由实现限定为有限枚举（例如 `minimal` / `strict`），用于控制提示内容强度。

## 验收标准（未来启用时）

- 启用开关为 `false` 时，重试链路不追加任何纠错提示，attempt 行为可通过日志与 `ai_request_logs` 载荷复现。
- 启用开关为 `true` 时：
  - 仅在 L0 失败时对后续 attempt 追加纠错提示。
  - 抢占后不再重试、不再追加提示。
