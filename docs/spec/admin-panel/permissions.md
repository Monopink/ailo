# 管理端权限规范

## 角色定义

- `super_admin`：可管理管理员账号，拥有全部权限
- `admin`：可查看和修改业务数据，不可管理管理员账号
- `viewer`：只读权限，不可执行修改操作

## 权限矩阵

| 功能 | super_admin | admin | viewer |
|---|---|---|---|
| 查看仪表盘/报表 | ✅ | ✅ | ✅ |
| 修改系统配置 | ✅ | ✅ | ❌ |
| 执行系统对话重初始化 | ✅ | ✅ | ❌ |
| 重新生成 Webhook Token | ✅ | ✅ | ❌ |
| Chat Console 联调（只读） | ✅ | ✅ | ✅ |
| Chat Console 调试写操作（如手工 ACK） | ✅ | ✅ | ❌ |
| 管理管理员账号 | ✅ | ❌ | ❌ |

## 审计要求

- 所有写操作必须记录到 `admin_operation_logs`
- 审计日志需包含：操作者、目标对象、操作类型、变更前后摘要、时间
- 高风险操作（如重置系统对话、重置 Token）必须记录明确操作来源

## 安全边界

- 前端仅做能力展示与交互约束，最终权限以服务端鉴权为准
- 禁止通过前端隐藏按钮替代真实鉴权
- `viewer` 角色进入调试页时，只允许查看，不允许触发写操作
