# 错误处理与降级规范

本文档定义错误处理、兜底与降级的统一语义与边界，用于约束服务端逻辑与客户端体验行为。

## 术语

- 体验降级：用户侧交互在异常或能力缺失时保持界面可用与流程可继续，按规范展示状态与提示，不影响用户继续使用主流程。
- 逻辑兜底：服务端因程序自身错误（bug、内部状态不一致、必需依赖缺失等）而静默回退到默认值、跳过必需校验、或返回看似成功的结果。
- best-effort 次要能力：失败不应影响主流程的能力（例如审计、部分实时扇出等）。失败时记录日志，主流程继续推进。
- 外部输入错误：来自客户端/第三方 Provider 的请求不满足接口契约或入站 Schema 的错误（缺字段、类型不匹配、越权、签名/鉴权失败等）。

## 基本规则

### 1) 逻辑兜底禁止（服务端）

- 必需依赖缺失、关键配置缺失、内部不变量被破坏属于硬错误，必须终止当前链路并返回明确错误。
- 当某个能力需要明确配置才能启用时，配置缺失必须视为错误或明确“未启用”，不得静默回退到默认行为。
- 允许降级的例外必须在对应 `docs/spec/*` 或 `docs/api/*` 中显式写明；未显式声明的降级/兜底属于不合规实现。

### 2) 外部输入错误允许兜底（入站层）

- 外部输入不满足契约时，必须在入站层拒绝或忽略非契约字段，且不得进入后续核心处理链路。
- 入站层的兜底范围以契约为准：仅对“允许缺失/允许为空/允许忽略”的字段执行兜底。

### 3) best-effort 次要能力允许失败

best-effort 次要能力允许失败必须同时满足：

- 失败不影响主流程的事实写入与核心状态推进。
- 失败必须记录结构化日志，包含可定位字段（例如 `request_id`、`user_qiao_id`、`instance_qiao_id`、`conversation_id` 等）。
- 该能力被声明为 best-effort（在对应 spec/api 文档中以约束条款出现），且失败语义清晰。

## 典型场景约束

### 入站校验失败

- 终止于入站层，不进入对话编排与 LLM 链路。
- 用户侧错误结构遵循 `docs/api/error-codes.md`。

### 安全检测失败

- 终止于安全层，不进入 LLM 链路。
- 对用户侧返回必须可预期且稳定（错误码/reason 为机器可读字段，客户端不得依赖文案分支）。

### 必需领域对象缺失

- `AIInstance`、`AIStyle`、`AIPersonality` 缺失属于硬错误，必须终止对话处理链路（见 `docs/spec/ai/conversation-flow.md`）。

### 会话副作用失败

- 会话副作用在独立事务边界内失败仅回滚失败项，已落地的消息事实保持不变。
- 失败必须记录日志用于排查（见 `docs/spec/ai/message-sending.md`）。

### Provider 投递失败

- 投递失败按统一失败处理链路推进，不改变消息事实定义。
- 失败处理细则见 `docs/spec/message/failure-handling.md`。

## 用户侧体验（客户端）

- 客户端在异常与能力缺失时必须保持页面可用，允许提示状态但不得阻断主流程。
- 与错误处理相关的客户端分支必须依赖机器字段（错误码、reason、action 等），不得依赖展示文案分支。
