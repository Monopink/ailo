# 移除短信验证登录功能

## 任务概述

移除小程序的短信验证码登录功能，只保留微信授权登录方式，简化登录流程和技术栈。

## 背景

- 当前系统支持三种登录方式：微信授权登录、短信验证码登录、手机号绑定
- 短信验证码功能需要对接真实短信服务商（阿里云/腾讯云），增加配置和维护成本
- 人机验证（Aliyun Captcha）集成存在问题，调试困难
- MVP 阶段希望简化技术栈，专注核心功能

## 产品决策

### 保留功能
- **微信授权登录**：使用 `wx.login()` + `getPhoneNumber` 获取用户手机号并完成登录

### 移除功能
- **短信验证码登录**：移除手动输入手机号+短信验证码的登录方式
- **手机号绑定页面**：移除 phone-bind 和 phone-login 页面

### 用户体验变更

#### 正常流程
1. 用户点击"微信授权登录"按钮
2. 授权手机号
3. 完成登录

#### 异常处理

**场景 1：用户拒绝授权手机号**
- 当前行为：跳转到 phone-bind 页面，提供短信验证码登录
- 新行为：提示"需要授权手机号才能使用本应用"，停留在登录页
- 影响：用户必须授权才能使用，无兜底方案

**场景 2：微信返回国际手机号**
- 当前行为：跳转到 phone-bind 页面，要求绑定 +86 手机号
- 新行为：提示"暂不支持国际手机号，请使用中国大陆手机号"，拒绝登录
- 影响：国际手机号用户无法使用（MVP 阶段可接受）

**场景 3：微信接口异常**
- 当前行为：可以使用短信验证码登录作为兜底
- 新行为：提示"微信服务异常，请稍后重试"
- 影响：依赖微信服务稳定性（概率较低）

## 风险评估

### 高风险

**风险**：用户拒绝授权后无法使用应用
- **影响**：可能导致部分用户流失
- **缓解**：在登录页明确说明需要授权的原因
- **接受度**：MVP 阶段可接受，大部分小程序都有类似要求

### 中风险

**风险**：微信接口异常导致无法登录
- **影响**：短时间内用户无法登录
- **缓解**：微信接口稳定性较高，概率较低
- **接受度**：MVP 阶段可接受

### 低风险

**风险**：国际手机号用户无法使用
- **影响**：国际手机号用户占比很小
- **缓解**：在产品说明中标注仅支持中国大陆用户
- **接受度**：MVP 阶段完全可接受
